INNOVATION

What Makes BioCascade Different?

Moving beyond single-biomarker approaches to multi-system cascade modeling

Cascade Interactions

Engineered features capturing multi-system dysfunction: Vascular-Metabolic Load (BP × HbA1c) and Metabolic-Renal Stress (HbA1c × 1/eGFR) ranked among the top predictors in the original Model A analysis. Their importance does not establish causal effects.

Novel Contribution

Full Interpretability

Predictions are explained using SHAP values, showing which features raise or lower the model score for each example. These contributions do not establish treatment effects.

Explainable AI

Two-Model Validation

Model A (0.9984 AUC): Upper-bound benchmark with target overlap. Model B (0.8293 AUC): Explores prediction using indirect markers. This dual approach makes target overlap explicit.

Methodology

Accessible Biomarkers

Model B explores demographics, anthropometrics and laboratory biomarkers without imaging inputs. Clinical utility and cost-effectiveness have not been established.

Research Accessibility

Independent Prediction

Independent markers provide predictive signal for the defined proxy. Longitudinal studies would be needed to assess early detection of disease.

Research Potential

Reproducible Research

Complete pipeline from raw NHANES data to deployment. Includes DuckDB for data management, scikit-learn for modeling, SHAP for interpretability, and Flask web interface.

Open Science

Key Findings and Model Limitations

⚡
Cascade Interactions: Interaction features (vasc-metabolic load, metabolic-renal stress) rank as top predictors in the original Model A analysis. This does not establish causation.
🎯
Independent Predictive Signal: Model B achieves a ROC-AUC of 0.8293, but positive-class precision remains limited.
🔬
Scientific Rigor: The two-model approach distinguishes target overlap from indirect prediction. External clinical validation is still needed.
ARCHITECTURE

The Interpretability Engine

End-to-end pipeline from raw data to explainable predictions

Data Pipeline

NHANES 2017-2018 (5,533 participants) → DuckDB storage → Feature engineering → Label definition (multi-system dysfunction proxy)

ML Training

Random Forest with class balancing → Two-model validation → Feature importance ranking → Held-out evaluation → Model persistence (joblib)

SHAP Explanations

TreeExplainer for global importance → Waterfall plots for individual examples → Feature contribution analysis → Model score interpretation

Technology Stack

Python 3.13 DuckDB scikit-learn SHAP NumPy / Pandas Flask HTML/CSS/JS Git
